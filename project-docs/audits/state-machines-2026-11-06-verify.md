## Must change

1. **J4 trim with J3 cleanup: moving the start back past a Reset and forward again destroys the Reset run's tail and its days.** Introduced in "fix: only a logged slip floors the start date, a Reset run is trimmed instead" (`02829e8`).
   - Route: a user with a Reset in their history (Home › ⋯ › Reset counter, say 20 days ago, after 29 sober days). Settings › Sobriety Start: tap a date before the Reset (a mis-tap, or trying it out; the binding writes on every set, `SettingsView.swift:282-293`), then pick the real date again.
   - What happens: the first set trims the Reset run to end at the tapped date (`SobrietyService.swift:92-93`). The second set moves the start later, so J3 deletes every unlogged sober row in [tapped date, real date) (`:49-57`), which are the Reset run's own days. Nothing restores the run's end. Lifetime days, money and calories drop by the gap, the longest streak shrinks to the trimmed run, and the gap belongs to no run. A user who taps every day keeps the rows but still loses the run's length (best streak 181 becomes 101 in the probe).
   - 9733bc3: no trim and no cleanup, so both sets left the Reset run and its rows as they were.
   - Proof: `probe_assumedDaysOfAResetRunSurviveAStartMovedBackThenForward` (Reset run 49 to 20 days ago, rows assumed; tap 40 days ago, then the Reset moment) reads lifetime 29 (want 49) and longest 21 (want 30). `probe_aResetRunsLengthSurvivesAStartMovedBackThenForward` (Reset run 200 to 20 days ago, every day tapped; tap 100 days ago, then back) reads longest 101 (want 181), lifetime 200 kept. Each asserts its controls first (lifetime and longest before, counter after each set), and they passed. Both pass on 9733bc3.
   - Direction for the fix: a start edit must be reversible. For example, keep closed runs as they are and clip them at read time to the next run's start (`longestStreakDays`, `reversibleSplit`), or remember a trimmed run's original end and restore it when the start moves forward past it; and limit J3's deletion to days no closed run covers. Turn both probes into regression tests.
