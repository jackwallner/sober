# Review of the Sober state machine audit, 2026-11-06

Independent review of [the audit](state-machines-2026-11-06.md) and [its repro suite](state-machines-2026-11-06-repro.swift), read against the code at `724395b` (build 118). Every route below was walked through the views, not just the services.

**Result: 19 claims. 6 CONFIRMED, 11 CONFIRMED-MINOR, 2 NOT A BUG, 0 UNVERIFIED.** Outright false positives: 2 of 19 (11%). Severity was mis-stated on about half of what survived.

## Test runs

- **Audit repro, rerun once:** gh-sim `sober@20261106-110753-d1bf-claude-imac79f3-1106-110923-14754`, iPhone 17. Same as the audit's run: 14 fail, `control` passes. A failing test only shows the service returns what the auditor's expectation rules out. Whether that expectation is right, and whether a user can reach it, is judged per row below.
- **Reviewer probes** (temporary `StateMachineAuditReview` suite, removed after the run): gh-sim `sober@20261106-110753-d1bf-claude-imac79f3-1106-112242-8074`, iPhone 17, 3 tests, all 3 fail as expected. Each asserts its precondition first. T2 and T3 controls passed, so their failures are the claim. Z1's row re-key control failed (the store's rows did not move to the new zone in the test host), so only the counter half of Z1 counts as proven by test.

## What survived, ranked

Ranked by users hit times cost to them.

1. **N1** stale reminders after a slip, Reset, undo or start edit. Common trigger, and the message ("You're 100 days in") lands on the worst morning a user of this app has.
2. **S1** undo reaches past the latest slip. Corrupts the run history (overlapping runs, counter reading through logged slips) and breaks on-screen copy.
3. **N2** daily reminder dead after the app's own "Allow notifications" recovery path.
4. **J3** start date moved later keeps the old days in lifetime days, money and calories, visibly ("Day 5 · 100 days sober"), with no way to delete them.
5. **T2** cancelled trials still told "before it renews". Low cost, high frequency.
6. **J1** older slip doesn't shorten the longest streak, right after copy promising it does.
7. **C1** check-in erases a slip. Severe, Duo only.
8. **N3** frozen daily copy.
9. **G4**, **G1** garden after a year: slip grows the tree; undo adds a phantom grove tree.
10. **T1**, **T3** trial reminder missing after a late grant, or quoting stale numbers.
11. **G5**, **G2**, **G3**, **J4**, **Z1** rare sequences, small or cosmetic cost.

The audit's grouping of fixes holds. Its order doesn't: C1 was ranked sixth on a device few users have, and G1/G4 were ranked above J1 and J3, which every user can reach.

## Missed by the audit

- **The daily reminder still fires after today's check-in.** Checking in reschedules the lapse and milestone nudges but not the daily one (`HomeView.swift:570-578`, `:779-797`), and the repeating request has no notion of today being done (`NotificationService.swift:100-105`). Someone who checked in at 9am is told at reminder hour "Log today and water your bonsai." Every reminder user, most days. Its title also says "Day \(streakDays + 1) is waiting" on the evening of day `streakDays`, one ahead of the "You're N days in" in the same notification (`:87-89`). CONFIRMED-MINOR by code; seen while checking N3, not hunted for.

Nothing more serious turned up inside the audit's scope.

## Method changes for the next 35 apps

Errors this audit made, and the change that would have caught each:

1. **Expected values were opinions (J2, and partly J4, S3).** J2's test asserts the opposite of a documented rule two lines from the code it tests. Rule: every assertion cites the promise it enforces (copy string, doc comment, AGENTS.md line) by file:line. No citation, no CONFIRMED; it goes in a "product calls" list instead. Grep the surrounding doc comments for the behaviour before writing the expectation.
2. **No check that the behaviour is a defect at all (K1).** The claim ignored that the target pauses with the timer and auto-lock is off. Rule: for each claim, write one sentence on what the user is told will happen, from the UI, and show the code contradicts it.
3. **Service tests stood in for reachability.** Every repro calls services directly. Rule: each claim carries a tap-by-tap route through named views, including date picker bounds (SlipSheet only allows the current run, `SlipSheet.swift:25-27`; Timeline blocks days before the first run and the future, `TimelineView.swift:333`, `:359-361`) and which control shows in that state. Where a route needs a special device or zone, say so in the verdict column.
4. **Impact was ordered by how bad the state looks, not who reaches it.** C1 (Duo only) and G1/G4 (366+ day streaks) outranked bugs every user can hit. Rule: an impact cell must name the precondition population (device, streak length, reminders on, trial state) and the frequency, and the ranking sorts on that.
5. **"A unit test can't show them" was wrong for 3 of 7 code-path claims.** T2 is testable through `SubscriptionService.processPurchaseResult` with a constructed `CustomerInfo` (the repo already does this in `SoberServicesTests.swift:56-125`), T3 through the existing `TrialLifecycle.notificationScheduler` seam, Z1 by setting `NSTimeZone.default`. Rule: before marking a claim code-path, list the app's existing test seams (injected schedulers, fixtures, defaults suites) and use them.
6. **Tests lacked in-test controls.** One global control can't show each precondition held. Rule: each test first asserts its precondition (e.g. `canUndo` is true before the bad undo, the zone switch took effect), so a failure means the claim and not a broken setup. This review's own Z1 probe shows why: its re-key control failed, which is the only reason the undo half wasn't wrongly reported as proven.
7. **Notification claims need a permission harness.** Three of the top four survivors are reminder bugs, and none could be run. Rule for the pilot: add a fake behind `NotificationService` (as `TrialNotificationScheduling` already does for trials) in apps that schedule reminders, or check the call graph exhaustively and list every scheduler call site in the evidence, as done for N1 and N2 here.
